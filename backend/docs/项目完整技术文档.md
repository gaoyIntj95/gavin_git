## 一、项目整体概述

### 1.1 项目定位与核心价值

**智碳管家（Carbon AI System）** 是一套面向企业的 **碳盘查 + 碳市场实时数据 + CBAM欧盟碳关税申报 + 双碳资讯** 一体化管理系统。

核心价值：
- **一站式碳管理**：从排放核算到履约交易，覆盖企业碳管理全生命周期
- **AI智能咨询**：接入大语言模型（Ollama本地 / 远程API），支持自然语言问碳数据
- **实时碳价监控**：全国碳市场（CEA）+ 欧盟碳市场（EUA）实时价格爬取，三层fallback保障数据可用
- **CBAM合规**：面向出口企业的欧盟碳关税自动计算与申报材料生成
- **双碳资讯聚合**：9大政府网站自动爬取，AI摘要 + 知识图谱构建
- **专业报告生成**：基于ISO 14064-1:2018标准的Word盘查报告一键生成

### 1.3 前后端交互流程

```
用户操作 → Vue组件 → callApi() → HTTP请求 → FastAPI路由 → Service层 → 数据库/外部API
                                                                          ↓
用户看到 ← Vue响应式渲染 ← JSON响应 ← FastAPI响应 ← 业务逻辑处理 ← 数据查询结果
```

- 前端使用 `callApi<T>(path, method, body)` 统一封装所有HTTP请求
- 自动附加 JWT Bearer Token 进行身份认证
- Chat类请求超时60秒，普通请求15秒，碳价请求45秒
- 支持多base地址自动fallback

## 三、核心业务模块详解

### 3.1 首页数据看板模块（HomeDashboard）

**前端文件**: `src/pages/HomeDashboard.vue`（1218行）
**后端接口**:
- `GET /api/projects` — 获取项目列表
- `GET /api/projects/{id}` — 获取项目详情（含report_year）
- `POST /api/projects/{id}/calculate` — 核算总排放
- `GET /api/projects/{id}/emission-sources` — 排放源列表
- `GET /api/timeseries/natural-gas/{id}` — 天然气时序数据
- `GET /api/timeseries/purchased-electricity/{id}` — 外购电力时序数据
- `GET /api/carbon-market/summary/{id}` — 履约汇总
- `GET /api/news/list` — 资讯列表

**展示内容**:
1. **项目选择器**: 下拉切换项目，联动刷新全部数据
2. **企业排放总览卡片**: Scope1/Scope2/合计，大数字展示
3. **年度履约状态卡片**: 配额持有量、配额缺口（正=缺口/负=盈余）
4. **排放结构速览卡片**: ECharts环形图（最多8个排放源+其他），自动生成减排建议文案
5. **近期碳排放趋势图**: 柱状图（月度排放）+ 折线图（3月移动均线），按项目report_year过滤
6. **待办事项列表**: 硬编码3项待办
7. **双碳行业资讯列表**: 分页展示、时间窗口切换、手动刷新、手动添加

**核心交互逻辑**（`loadDashboard`函数）:
```
1. 获取项目信息 → 获取report_year
2. 并行请求: 核算结果 + 排放源 + 天然气时序 + 电力时序
3. 时序数据按月份聚合 → 生成12个月完整数据（有缺失则为0）
4. 计算3月移动均线（边界处理：第1月=当月值，第2月=2月均值，第3月+ = 3月均值）
5. 渲染ECharts柱状图+折线图
6. 渲染排放结构环形图
7. 尝试获取履约数据，失败则估算（月均*12*0.92）
```

**时序数据兜底**: 如果当前项目没有时序数据行，自动fallback到项目1（种子数据所在项目）

### 3.2 碳盘查与排放数据模块

**前端页面**: `CarbonCalculationPage.vue`、`ProjectManagementPage.vue`
**后端接口**:
- `POST/GET/PUT/DELETE /api/projects` — 项目CRUD
- `POST/GET /api/projects/{id}/emission-sources` — 排放源管理
- `POST /api/projects/{id}/calculate` — 触发核算
- `POST /api/reports/inventory/{project_id}` — 生成盘查报告

**核算公式**（`calculation_service.py`）:
```
总排放 = Scope1(直接排放) + Scope2(间接排放) + Scope3(其他间接排放)
Scope1 = 固定燃烧 + 移动燃烧 + 工艺排放 + 无组织排放
Scope2 = 外购电力 + 外购热力
```

**排放因子库**（`factor_library.py`）:
- 预置4个标准排放因子（基于JS/T 303-2026）：

### 4.1 项目年度联动图表逻辑

前端 `HomeDashboard.vue` 的 `loadDashboard()` 函数实现了完整的项目-年度联动：

```

2. 获取项目report_year → 用year参数过滤时序数据
3. 生成1-12月完整数组（无数据的月份填0）
4. 聚合天然气+外购电力的月度CO2e
5. 当前项目无时序数据时，自动fallback到项目1的数据
```

**关键代码位置**: `HomeDashboard.vue:416-581`

### 4.2 3月移动均线计算规则

在 `HomeDashboard.vue:539-555` 实现的边界处理逻辑：

```typescript
// vals = [m1, m2, m3, m4, ...]
for (let i = 0; i < vals.length; i++) {
  if (i === 0) {
    trend[i] = vals[i]              // 第1月: 等于当月值
  } else if (i === 1) {
    trend[i] = (vals[0] + vals[1]) / 2  // 第2月: 2月均值
  } else {
    trend[i] = (vals[i-2] + vals[i-1] + vals[i]) / 3  // 第3月+: 标准3月均值
  }
}
```

### 4.3 碳价/资讯三层fallback架构

两种三层fallback的通用模式：

```
                    ┌──→ Tier 0: 实时爬取（优先级最高）
用户请求 ──→ 尝试 ──┤
                    ├──→ Tier 1: API/搜索（Tier 0失败时）
                    │
                    └──→ Tier 2: 数据库缓存/硬编码值（最终兜底，永不会失败）
```

- **碳价fallback**: `tanpaifang.com爬虫 → AKShare API → 硬编码参考价`
- **资讯fallback**: `9大来源HTML爬取 → 关键词API搜索 → 数据库缓存`

每层结果都会在 `fallback_layer` 字段中标记（0/1/2），前端据此显示不同的UI提示（实时/缓存/离线）

### 4.4 异步爬虫 + 前端防超时处理

**后端**（`news.py`）:
- 爬虫任务在后台线程执行（`threading.Thread`）
- 任务状态用内存字典 `_refresh_tasks` 跟踪
- 超时保护：`REFRESH_TASK_TIMEOUT_SEC = 300`秒
- 爬虫冷却：触发429限流后自动暂停1小时

**前端**（`HomeDashboard.vue`）:
- 发起 `POST /api/news/refresh` → 获得 `task_id`
- 每2秒轮询 `GET /api/news/refresh-status?task_id=xxx`
- 最多轮询100次（~200秒）后自动停止
- 完成后自动调用 `loadNews()` 刷新列表

**`useApi.ts` 超时配置**:
- 普通请求: 15秒
- 聊天请求: 60秒（不启用AbortController）
- 碳价请求: 45秒
- 文件上传: 60秒
- 认证请求: 30秒

### 4.5 数据库缓存与数据兜底机制

**资讯缓存**: 
- 所有爬取的资讯存入MySQL `industry_news` 表
- 向量嵌入存入Milvus `carbon_ai_news` collection
- 去重策略: `source_url` 唯一索引 + `fingerprint` (MD5(title+date+source)) 唯一索引

**碳价缓存**:
- 内存缓存（10分钟有效期）
- `force=true` 可绕过缓存强制刷新

**排放因子缓存**:
- 预置在 `factor_library` 表，启动时自动seed（如果为空）

**时序数据兜底**:
- 当前项目无数据时，自动fallback到项目1（种子数据）

## 七、常见问题与排查方案

### 7.1 接口超时 signal aborted 问题

**现象**: 前端请求报 `AbortError: signal is aborted`

**原因**: `useApi.ts` 中非chat请求默认8秒超时，超过时间未响应会触发 `AbortController.abort()`

**排查步骤**:
1. 检查后端是否正常运行（`curl http://127.0.0.1:8017/health`）
2. 碳价/爬虫类接口内部有网络请求，容易超时（已配置45秒超时）
3. 如果频繁超时，可增大 `useApi.ts` 中对应路径的timeout值
4. Chat请求不启用AbortController，依赖LLM自身超时

### 7.2 爬虫失败兜底逻辑

**资讯爬虫三层fallback**:

| 层级 | 触发条件 | 效果 |
|------|---------|------|
| Tier 0 失败 | 429限流 / 网络不通 / HTML结构变化 | 自动进入Tier 1 |
| Tier 1 失败 | 站内搜索无结果 / API不可用 | 自动进入Tier 2 |
| Tier 2 | 永远可用 | 展示数据库历史缓存 |

**429限流特殊处理**: 一旦触发429，自动设置1小时冷却期，期间所有爬取请求被跳过

**调试**: 
- `GET /api/news/debug` — 查看爬虫状态、冷却期、各来源数据量
- `POST /api/news/refresh-sync` — 同步刷新并获取完整trace日志

### 7.3 图表无数据问题

**趋势图为空**: 
- 检查项目是否设置了 `report_year`
- 检查该项目是否有天然气/外购电力时序数据
- 当前项目无数据时会自动fallback到项目1

**饼图为空**:
- 检查项目是否有排放源数据（`GET /api/projects/{id}/emission-sources`）
- 饼图只显示 `co2e > 0` 的排放源

### 7.4 前端渲染异常问题

**页面空白**:
- 检查 `localStorage` 中是否有 `access_token`
- 未登录时会渲染 `LoginPage`，登录后才会显示主界面
- 默认账号: `admin` / `admin123` 或 `demo` / `demo123`

**类型错误**:
- 后端返回数据格式变化时可能导致前端类型不匹配
- 检查浏览器console中的具体错误信息

**打包构建**:
- `npm run build` 生成dist目录
- 生产环境需配置nginx反向代理 `/api` 到后端8017端口

## 八、开发约定与注意事项

1. **前端无Vue Router**: 所有页面切换通过 `App.vue` 中的 `activePage` ref + `component :is` 动态组件实现，非传统SPA路由
2. **认证方式**: JWT Bearer Token，存储在localStorage，无刷新token机制
3. **权限控制**: 仅 `admin` 角色可执行 PUT/PATCH/DELETE 操作（`useApi.ts:93-96`）
4. **数据库**: 仅支持MySQL，SQLite已移除（`database.py:8-10` 强制校验）
5. **软删除**: 项目使用 `is_deleted` 字段实现软删除
6. **日志**: 应用日志写入 `D:\CarbonAI\logs\carbon_ai_app.log`，10MB轮转保留5个
7. **CORS**: 仅允许 `127.0.0.1:5173/5174/5500/5501` 来源
8. **Agent安全**: 工具白名单机制，任何非白名单工具调用会被拦截
